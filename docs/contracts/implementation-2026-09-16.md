# 研究数据复核：开发交付说明

日期：2026-09-16。分支：`codex/hybrid-research-review`。本地版本：0.5.0。

本轮完成本地开发、独立代码审查、回归验证、浏览器检查和三家已配置模型的有界实测。尚未推送、部署或启动生产全库重算；线上配置和当前选中的模型未被测试修改。开发中使用的 GPT-5.6 Luna Max 不参与线上定时任务。

## 处理流程

1. 服务启动及每小时检查报告来源，并明确计算新增、修改、删除。新增或修改内容按原文哈希进入持久队列；相同内容和处理版本不重复付费。规则、提示词、复核协议或自动模型策略版本变化时，已有报告按新处理版本重新排队；旧结果在新结果完成前继续保留。纯切换网页模型不自动重跑已完成历史任务。
2. 程序解析原文，生成文章、提及、观点、信号、主题和证据六类候选。候选语义可以错误；原文、位置、记录引用必须完整。
3. 线上自动任务固定使用最近保存的 DeepSeek profile，与网页当前选中的 AI 无关；领取任务时会替换旧版本遗留的其他模型 pin，随后固定 DeepSeek profile 和复核参数。AI 读取完整分块原文及候选，提交 keep/add/modify/delete/defer。每个 profile 仍单独加密保存 Key；任务途中不混用模型。网页当前模型仍可用于对话和人工测试。
4. 程序校验有限字段、旧值哈希、枚举、原文证据位置、评级和价格字面依据、公司及文章引用。名称边界可纠正，标准证券身份由程序重新匹配。修正完成的问题保留 resolved 审计记录。
5. 格式或语义校验失败时，只允许一次携带具体错误的纠错请求；再失败则不发布。截断最多拆分两层，保留成功分块断点。每次请求均经过共享预算预留。
6. 合格结果生成统一发布版本。公司研究、观点速览、检索、关注列表和助手读取同一版合格事实。完整但含歧义的结果可隔离不合格记录，其余结果发布为部分完成；未完成的整份结果不取代原有合格版本。
7. 报告及证据链接保存内容哈希。新报告修改后，旧引用仍打开对应历史原文；没有匹配的旧版本不会偷偷跳到新原文。已公开的历史版本保留可访问性，来源撤回只退出当前默认视图。

已有报告启用后进入同一队列，有预算则逐步处理。来源快照是完整读取后才提交队列；若报告文件读取失败，不会把失败的空列表当成删除。新报告进入 queued；原文变化生成新的 sourceHash 和 job，旧 job/result 保留审计；原文缺失的报告标为 withdrawn，从当前发布撤出但不删除源文件、结果或历史引用。未复核规则结果不再混入合格统计，用户可展开“程序草稿”查看。规则匹配、AI 复核、人工确认是不同状态。

## 六类结构和主要枚举

运行时唯一枚举入口是 [`src/shared/researchVocabulary.ts`](../../src/shared/researchVocabulary.ts)，合同类型在 [`api/domain/review.ts`](../../api/domain/review.ts)。JSON 词汇表是设计查阅材料，早期全量提取 Schema 不作为生产 Patch 协议。

| 类别 | 主要内容 | 固定选项 |
| --- | --- | --- |
| 文章 article | 类型、机构、日期、摘要、主体与主题引用 | 公司/行业/宏观/策略/混合/未知 |
| 提及 mention | 原文名称、原始代码、角色、身份解析 | 主体/推荐标的/同行/客户供应商/发布机构/分析师/术语/其他/未知；解析成功/歧义/未解析/冲突 |
| 观点 statement | 主体、归属机构、评级、建议、目标价、此前值、依据及时间条件 | 评级：买入/增持/中性/持有/减持/卖出/其他原文评级；评级动作：维持/上调/下调/首次覆盖/恢复/撤回/其他 |
| 信号 signal | 风险或催化剂、影响对象、事件、时间和条件 | 风险/催化剂；当前/历史/未来/未知；肯定/否定/未知；实际/条件性/假设/未知 |
| 主题 topic | 行业、主题或市场范围，原始标签及来源 | 行业/主题/市场范围；原文标签/AI 提取/人工；候选/已批准/弃用 |
| 证据 evidence | 报告和版本、行列、字符偏移、原文切片、字段引用 | 程序生成，AI 仅引用；不能新增或改写原文证据 |

每个 Claim 区分“原文明示、未提及、歧义、不适用”；歧义保留多个有证据的候选，主值为 null。评级同时保留原文术语、体系、基准和期限，不能把积极语气直接归为买入。目标价支持点值/区间，保留币种、单位、期限和原始文本。枚举中的人审和事件兑现状态为结构预留，不代表本轮已提供完整人工审核台或事件追踪产品。

## 证券身份与规则修正

代码优先，但仍检查语境和公司名称是否冲突。支持无后缀 600098、0700、BZ；港股前导零保留。公司、证券和挂牌使用不同稳定身份，不把 A/H/ADR 简单合并为同一交易标的。仅提及公司时不凭常识补具体挂牌。

保留 2026-09-09 证券目录快照及来源限制；新增有公开来源的 BOSS 直聘/BZ 别名。目录不是完整历史证券主数据，也没有实现实时全球全量更名、退市和公司行为同步。美股目录中的未知工具类型不自动标成普通股。

真实 2026-09-08 回归包含：国电南瑞连接语清理；野村标题不作为公司、其后四股共用买入评级且各自绑定价格；赣锋与天齐评级分别归属；中国移动的 CM 与储能 ESS 等缩写不被自动当美股代码；未评级同行不继承推荐主体评级。

## 三家模型实测

所有测试调用位于服务器隔离临时目录，复用对应 profile 的 Key；没有往生产报告队列写入测试样本。没有降低证据校验来获取“通过”。

第一组为真实日报第 16 行节选和机构标题，验证四家公司及各自买入评级、目标价。参数适配后均返回完整合格结果：

| 模型 | 结果 | 供应商返回 token | 耗时 |
| --- | --- | ---: | ---: |
| OpenRouter / z-ai/glm-5.3-flash | 4 家公司正确，完整有效 | 16,979 | 3.648 秒 |
| DeepSeek / deepseek-flash | 4 家公司正确，完整有效 | 16,225 | 2.343 秒 |
| MiMo / mimo-v2.5-pro | 4 家公司正确，完整有效 | 20,103 | 11.408 秒 |

第二组是明确标记的合成纠错样本：候选中注入“同时覆盖国电南瑞”、错误目标价 60 元、假公司“首选标的组合”，并漏掉项目验收催化剂。正确结果为国电南瑞、买入、28 元、排除栏目并补充催化剂。

- 三家首轮均理解了主要错误，但没有遵守修改协议；因此全部拦截。补齐公共操作示例后继续测试。
- 最新 DeepSeek 通过一次反馈纠错，完成四项目标；两次请求共 27,710 token。但把 10 月预期事件标为 current，且把程序词库补充的代码误报为缺少原文依据，尚未达到完整语义标准。最终提示词已补充报告日期和词库字段解释，尚未再次付费验证。
- 最新 GLM 在一次反馈纠错后仍输出重复候选操作，未通过；两次请求共 27,421 token。
- MiMo 第二轮存在多余字段及悬空引用，未通过。最新一轮已计量一次请求 15,343 token，但后续纠错所需预留超过剩余测试额度，在发出请求前停止，没有形成完整验收结果。

因此不能宣称三个模型已达到相同效果，更不能据此宣布全库准确。当前更适合作为“严格校验、失败待核对”的开发版本；三家模型尚未全部达到本组纠错样本的完整语义和协议验收标准，不建议直接开启无人关注的历史全库重跑。并未擅自切换网页当前模型。

结构化输出的格式适配：MiMo 显式关闭思考并启用 JSON mode；OpenRouter GLM 使用低推理，因为该测试端点拒绝禁用思考；DeepSeek 使用明确的 thinking 设置。参考 [MiMo 思考模式](https://mimo.mi.com/docs/zh-CN/quick-start/usage-guide/text-generation/deep-thinking)、[MiMo JSON mode](https://mimo.mi.com/docs/zh-CN/quick-start/usage-guide/text-generation/structured-output)。格式正确仍需代码和语义检查。

实测记录在 [`implementation-validation/`](implementation-validation/)。历史设计阶段测评仍单独保留，不能与本轮样本混算准确率。各次测试的已知用量据供应商记录结算，未知用量保留预留；最后累计核算 469,929 单位，其中可计量 token 为 336,717，其余 133,212 为未知用量的保守预留。此数包括前序设计和开发测试，不是一篇日报的消耗。当前协议的短节选也消耗一万多 token，尚不能承诺混合方案更省 token。

## 验证与运行边界

- 88 个测试文件全部通过；新增纠错重试、固定 DeepSeek 策略及 resolved 审计回归再次单独通过。
- `npm run lint`、`npm run check`、`npm run build`、`git diff --check` 通过。
- 浏览器使用隔离假 Key：验证 DeepSeek/MiMo 各自复核参数；桌面和 390px 移动宽度配置页；规则草稿独立展示；证据链接进入历史原文模式。
- 回归覆盖队列重启、配置暂停、有限重试、预算恢复、成功分块复用、截断拆分、旧规则缓存隔离、原文版本链接、同公司多挂牌和共同评级。

运行要求单个持久 API 进程。后台最多一项任务；与对话共用并发名额并记录估算/实际用量。应用不再按每日 Token 数拦截请求，费用和额度由服务商 Key 控制。默认复核超时 120 秒、输出上限 8000 token，可在每个 profile 中分别设置。完整报表、跨文章复杂指代、长期历史身份和大规模模型准确率尚未得到本轮实测证明。历史批处理耗时取决于报告分块数和当前模型吞吐，不能用一条节选外推全库完工时间。

本轮没有上线发布，也没有清空旧数据。后续发布须沿用 GitHub main 验证后服务器同步的顺序，并在实际部署环境验收 DeepSeek 固定选择、增删改报告、队列恢复和小批报告，再决定扩大历史处理范围。
