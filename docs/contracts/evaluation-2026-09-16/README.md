# 三个已配置模型的小样复核评估

日期：2026-09-16（北京时间）。来源：当前网页保存的三个独立profile，服务器配置读取验证，代码基线v0.4.4 / `6ed751a`。本次没有改变当前profile、Key或线上事实。

## 方法和范围

固定8个样本，包含4段2026-09-08真实报告原文及4个明确标注的构造样本。真实原文由仓库哈希校验fixture读取；程序候选用当前 `extractOpinions` 生成。金标准在供应商请求前写入 [gold.json](gold.json)，包含18条当前评级/目标价组合。

| 样本 | 检查点 |
| --- | --- |
| R1，原文第16行 | 同时覆盖国电南瑞；四家公司的评级和价格 |
| R2，第223行 | 野村共同评级；伪标题公司；代码数字误作目标价；原文港元矛盾 |
| R3，第197—200行 | 赣锋/天齐漏评级；ESS术语；行业风险不串成公司目标价 |
| R4，第627—635行 | 中国移动/CM身份；长飞光纤价格；未评级同行 |
| S1，构造 | 600098/0700/BZ无后缀代码 |
| S2，构造 | 评级下调、原价/新价、未覆盖、历史与条件性买入 |
| S3，构造 | 共同评级与分别定价；AH标签；独立风险和催化剂 |
| S4，构造 | ESS/CM术语和简称；原文中的提示注入 |

原始样本及候选见 [samples.json](samples.json)。这是有针对性的调参样本，**没有独立留出集，不是完整六类结构或全日报基准**。原文里写入的指令被作为待分析数据，不作为用户要求执行。

## 三轮设置

1. `base`：所有模型使用相同基础提示词；复用当前供应商认证与采样设置，非流式返回，最大输出6000，超时45秒。
2. `common`：同一份公共规则v1；输出上限仍6000，超时放宽到120秒。不能将超时改善归因于提示词。
3. `adapted`：公共规则v2，程序提供允许标签和候选ID；要求紧凑JSON及精确引用。GLM/DeepSeek最大输出4000，MiMo9000，超时180秒；DeepSeek单独关闭默认推理，GLM维持low reasoning。参数适配与提示词同时改变，**不是受控的纯提示词A/B，也不是模型性能排名**。

基础提示词：[prompt-base.txt](prompt-base.txt)。公共v1：[prompt-common-extra.txt](prompt-common-extra.txt)。v2追加规则：[prompt-common-v2-extra.txt](prompt-common-v2-extra.txt)。v2引用已知反例，属于针对本组样本的迭代，不宣称泛化成绩。

## 观察结果

| 网页模型 | 基础轮 | 公共v1轮 | 最后一轮 |
| --- | --- | --- | --- |
| OpenRouter / z-ai/glm-5.3-flash | 18/18核心字段；20/26引用逐字命中；伪标签和候选ID错误 | 18/18；28/33逐字命中；仍有伪标签和ID错误 | 18/18；43/44逐字命中；额外字段导致Schema不通过，且把YOFC当作原文股票代码 |
| DeepSeek / deepseek-flash | 6000输出token全部消耗于推理，无JSON正文 | 同样耗尽6000推理token，截断 | 关闭推理后18/18，24/24逐字命中，Schema通过；但共同评级证据链不完整，且催化剂分类错误 |
| MiMo / mimo-v2.5-pro | 45秒超时；未获取usage | 约110秒返回6000token后截断，未完成8个样本 | 18/18；21/21逐字命中，Schema通过；共同评级证据链缺失、币种疑点未标、一个原文明示机构漏填 |

“18/18核心字段”只衡量公司名、当前评级、目标价金额及币种组合；不包括所有代码、机构、事件、证据充分性和修改合法性。逐字命中率只证明引文出现在原文，不证明引文支撑了所有字段。完整的逐次统计见 [scores.json](scores.json)。不对截断JSON做字符串补齐后算作成功。

### 人工语义审核的关键发现

- GLM在最后一轮给信号添加了未定义的 `note:null`，严格Schema拒绝；思源电气有一处引用不是原文连续子串。长飞光纤的 `YOFC` 被当成rawCode，并根据程序候选的A股代码推断“原文代码为A股口径”；这是原文与系统身份混淆，不能只用正确评级/价格掩盖。
- DeepSeek最后一轮四家公司的买入评级值都正确，但每条只引用各自价格括号，没有引用“评级均为买入”的共同范围，证据无法独立支持评级；R3把“需求韧性支撑中期前景”标为催化剂，违背本轮要求的具体事件语义。
- MiMo最后一轮同样未给四个买入字段附上共同评级原句；R2虽保留港元，却未标明与代码市场的疑点；S2明示的“示例券商”被填成null。R3未提及ESS出货放缓风险，事件召回仍需单独评估。
- 三个模型都需要外部程序验收。靠更长提示词不能消除全部错误，正式协议应优先让模型引用程序分配的证据片段ID，并由系统保留原始坐标，而不是要求模型反复抄写含Markdown的长引文。

本轮结论：混合方式确实能修正现有规则的关键漏项和错绑，但**不能据此批准任一profile自动发布完整六类结构**。应完成正式Patch协议、字段证据检查、供应商适配和真实留出集回归后再上线。

## 参数问题的依据

DeepSeek当前官方接口默认启用thinking，支持 `thinking.type=disabled`；推理额度占用输出预算。实测前两轮均把6000输出token用在reasoning，最后一轮关闭后恢复正文输出。该设置只用于本次测试，没有写回网页配置。[DeepSeek官方接口文档](https://api-docs.deepseek.com/api/create-chat-completion/)

结构化输出可约束JSON结构，但不能保证值与证据的语义正确；还须处理不完整输出、拒绝等分支。本次未启用所有供应商的原生严格Schema模式，使用相同文本协议加本地Ajv验收，不能把结果解释为各供应商原生结构化能力测试。[OpenAI官方说明](https://developers.openai.com/api/docs/guides/structured-outputs)

## 用量、隔离与复现

共执行9次请求；8次取得usage，供应商报告合计 **68,031 token**，另1次MiMo超时用量未知，不能据此报总费用或把未知算零。最后一轮GLM/DeepSeek/MiMo分别为7,001/6,547/12,046 token，耗时24.273/6.445/105.646秒；仅代表本组样本与本轮参数。

本次评估单独设置20万token保守预留上限，串行调用并读取线上每日额度余量；每次请求使用输入UTF-8字节数加输出上限及余量做预留。最终保守预留199,112/200,000，测试已停止。它不是精确token计量，失败预留也未释放。实际用量以响应usage为准，超时未知不当作零。

测试账本单独保存在临时目录，未写入对话服务的额度文件；因此本次评估用量需单独看，不能误认为网页日额度统计已包含它。正式后台上线必须使用与对话同一个进程内资源管理器及持久化账本，避免跨进程预留竞争。本次脚本是显式运行的评估工具，不可直接当生产定时任务。

每次请求后核对配置文件哈希未变；密钥只在服务器内存中解密和发往对应配置地址，不进入输出文件，不切换profile。受限临时输出只保存JSON正文、usage、响应状态与配置不变标记，不保存推理正文、认证头或供应商错误正文。

复现材料：

- `build-samples.ts`：离线生成样本/当前规则候选，真实fixture有哈希检查。
- `run-server.cjs`：显式执行的供应商评估工具；会产生费用，不属于项目启动流程。
- `response.schema.json`：本次小样输出Schema，不是正式ReviewPatch。
- `score.cjs`：离线核心字段、引文、标签、ID与Schema检查；不代替语义审核。
- `base/common/adapted-*.json`：逐次脱敏结果，不能覆盖失败记录只保留最后成功。
